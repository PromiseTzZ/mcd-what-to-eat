# mcd-what-to-eat · 今天中午吃什么

> 一句话，把「翻菜单、算券、猜热量」变成一张五档对比表。

基于麦当劳官方 MCP（`mcp.mcd.cn`）的点餐决策 Skill。用户说一句「今天中午吃什么」，
它拉真实门店菜单、真实优惠券、真实营养数据，给出五档推荐：**最低卡 / 最省钱 / 兼顾 / 惊喜 / 单品自由搭**。

默认只推荐，绝不下单。

---

## 它解决什么问题

| 用户现在要做的事 | Skill 自动完成 |
|---|---|
| 打开 App 翻菜单，跳过已售罄和不在时段的 | `query-meals` 按门店 + 时段建候选池 |
| 记住自己有哪些券、什么时候过期 | `available-coupons` + `query-store-coupons` + `query-my-coupons`，逐张校验 |
| 心算哪个组合券后最便宜 | `calculate-price` 逐个实算，不心算 |
| 猜一个汉堡多少大卡 | 官方营养库精确值，缺失时分级溯源并标区间 |
| 在「想吃爽」和「不想胖」之间纠结 | 五档推荐，把选择权还给你 |

## 五档推荐

| 档位 | 选什么 | 规则 |
|---|---|---|
| 🥗 **最低卡** | 热量最低的候选 | 热量已知者中最低；并列取券后价低 |
| 🎫 **最省钱** | 券后价最低 | 并列取热量低 |
| ⚖️ **兼顾** | 帕累托前沿上的折中解 | 先求非支配集，再按热量/价格各 50% 归一化加权 |
| 🎲 **惊喜** | 其余候选里随机一个 | 附一句值得一试的理由（新品 / 限定 / 活动联动） |
| 🧩 **自由搭** | 单品自由组合，非套餐 | 如「汉堡 + 零糖饮品」，并与对应套餐比价 |

## 为什么不是又一个「Top3 比价器」

**1. 五档决策，不是一张榜单。**
比价器只回答「哪个最便宜」，但中午真正纠结的是「便宜的会不会太难吃」「今天想放纵还是想控卡」。
五档把这个问题拆成五个明确的取舍方向，而不是让用户在十几个价格相近的套餐里继续纠结。

**2. 热量四级溯源，禁止「未知」和编造。**
官方营养库只收约 160 条**单品**、不含套餐，且与门店菜单是两套命名。本项目按
A（官方营养库精确值）→ B（官方渠道联网补查，附链接）→ C（同品类近规格折算，写 ≈区间 + 折算基准）→
D（确实无据，明说缺失并注明已试过的来源）取值，输出带来源上标。
任何一行都不会出现凭空估算的「看似精确的单值」。

**3. 券的有效性先于价格。**
券能不能用由「有效期 + 门槛 + 限定品类 + 限定时段」四项共同决定。实测中经常遇到门店券只到今晚 23:59
的情况——如果只看券名单，就会给出一个明天根本兑现不了的「券后价」。本项目先校验，再算价。

**4. 只推荐，不下单。**
`create-order` / `cancel-order` 只有在用户明确回复「下单」并确认取餐方式后才会调用。

## 安装

### 1. 申请自己的 MCP Token

打开 <https://open.mcd.cn/mcp> → 手机号登录 → 右上角「控制台」→ 激活 → 同意协议 → 复制 Token。

Token 跟随注册账号，券包、积分、订单查的都是这个账号的数据，**每人一份，不要共用**；
Token 等同密码，不要提交到公开仓库或发到群里。服务免费，限流 600 次/分钟。

### 2. 配置 MCP 连接

所有客户端参数相同：

- 传输协议：**Streamable HTTP**
- URL：`https://mcp.mcd.cn`
- Header：`Authorization: Bearer <你的 Token>`

配置示例见 [`mcp-config.example.json`](mcp-config.example.json)（仅含环境变量占位符）。

> `type` 字段各客户端取值不同：Cherry Studio / Cursor / WorkBuddy 用 `streamablehttp`，
> **Qoder / Claude Code 用 `http`**，部分老客户端只认 `sse`。`url` 和 `headers` 不变。

### 3. 安装 Skill

把 `skill/mcd-what-to-eat/` **整个文件夹**（含 `references/`）复制到客户端的技能目录：

| 客户端 | MCP 配置 | Skill 安装位置 |
|---|---|---|
| **Qoder** | 设置 → MCP → 添加，传输类型选 HTTP | `~/.qoder/skills/` |
| **Claude Code** | `claude mcp add --transport http mcd-mcp https://mcp.mcd.cn --header "Authorization: Bearer <Token>"` | `~/.claude/skills/` 或项目 `.claude/skills/` |
| **WorkBuddy** | 自定义连接器 → 配置 MCP，粘贴 JSON | 技能/专家面板 |
| **Codex CLI** | `~/.codex/config.toml` 的 `[mcp_servers.mcd]` | 正文并入 `AGENTS.md` |
| **Gemini CLI** | `settings.json` 的 `mcpServers` | 正文并入 `GEMINI.md` |
| **VSCode (Copilot)** | 工作区 `.vscode/mcp.json` | `.github/copilot-instructions.md` |
| **Cursor** | Tools & MCP → Add Custom MCP | 项目规则目录 |
| **TRAE** | 设置 → MCP → 手动添加 | 项目规则文件 |
| **Cherry Studio** | 设置 → MCP → 从 JSON 导入 | 无技能机制，正文粘进助手提示词 |
| **DSH** | 用 `mcp-bundle/`，替换 `YOUR_MCP_TOKEN` 后安装 | `~/.dsh/skills/` |

> 不支持技能机制的客户端：把 `SKILL.md` 正文粘进系统提示词或规则文件即可。
> 工具名前缀随客户端不同（`mcp__mcd-mcp__`、`mcp__mcd__` 或无前缀），Skill 内部按**后缀**匹配，不用改。

各客户端的详细步骤、故障排查见 [`skill/mcd-what-to-eat/references/setup.md`](skill/mcd-what-to-eat/references/setup.md)。

## 使用示例

**用户**：明天午餐吃什么
**助手**：你在哪个位置？（给出门店后开始拉菜单）

**用户**：中关村科技大厦

**助手**（2026-10-24 周六 12:00 到店自取，价格由 `calculate-price` 实算）：

| 档位 | 内容 | 原价 | 券后价 | 用的券 | 热量 | 一句理由 |
|---|---|---|---|---|---|---|
| 🥗 最低卡 | 麦香鸡（单品） | 16.50 | 16.50 | 无 | 369¹ | 全店汉堡热量地板，单点不配薯条就不会超 |
| 🎫 最省钱 | 人气经典随心配：双层吉士汉堡 + 可乐麦炫酷 | 14.90 | 14.90 | 无 | ≈630–670³ | 14.9 拿下双层吉士，比单点（22.5）还便宜 |
| ⚖️ 兼顾 | 龙焰鸡腿堡（单品） | 24.00 | 15.90 | 无券，菜单直降 8.10 | ≈460–520³ | 价格第二低、热量居中，还是当期新品 |
| 🎲 惊喜 | 咸蛋黄鸡腿蛋月堡三件套 | 26.90 | 26.90 | 无 | ≈1000–1100³ | 咸蛋黄酱夹整块蒸蛋，普通汉堡尝不到的口感 |
| 🧩 自由搭 | 麦辣鸡腿汉堡 + 纯悦 | 30.00 | 30.00 | 无 | 485¹ | 去掉薯条可乐，比三件套省 3.5 元、少 436 kcal |

¹ 官方营养库精确值　³ 同品类折算估算（输出时附折算基准）

**助手补充**：两张门店券今晚 23:59:59 到期，明天用不了，所以以上均为原价。要下单吗？

> 用户还可以继续追加约束：「我想吃汉堡」「预算 30」「不吃辣」「两个人」——
> Skill 会先过滤候选，再重新出五档。

## 目标用户

- **每天纠结吃什么的上班族**：不想花十分钟翻菜单，只想看一眼就决定。
- **控卡但不想戒麦当劳的人**：需要知道确切热量，而不是「大概挺高的」。
- **有券但懒得算的人**：券多、门槛杂、还有有效期，手动算不过来。
- **帮别人点餐的人**：给同事、家人配一份不踩雷的餐，还能照顾口味和预算。

## 已知限制

- **营养库覆盖不全**：官方库约 160 条单品，新品、联名款、套餐均需拆分或折算，估算值会以 ≈ 区间呈现。
- **券因账号而异**：券包、积分、会员等级都绑定账号，不同人跑同一家店可能得到不同券后价。
- **菜单随时段变化**：早餐与正餐是两套菜单，跨天或跨时段推荐必须传 `reservationDate`。
- **价格以结账为准**：表中价格为 `calculate-price` 返回的实时结果，最终以 `create-order` 为准。
- **不做营养建议**：热量数据仅供参考，不构成医疗或营养专业意见。
